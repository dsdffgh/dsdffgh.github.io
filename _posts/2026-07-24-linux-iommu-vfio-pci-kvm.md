在 Linux 上，硬件直通（如 IOMMU/VFIO/PCI 直通）主要依赖于硬件和内核支持，而不专属于 KVM。IOMMU（Intel VT-d 或 AMD-Vi）是主板和 CPU 提供的硬件功能，用于将设备的 DMA 请求限制到特定内存，从而实现安全的设备直通。Linux 内核通过启用 intel_iommu=on（或 amd_iommu=on）等启动参数来激活 IOMMU[[1\]](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/5/html/virtualization/chap-virtualization-pci_passthrough#:~:text=2. Activate Intel VT,the kernel)[[2\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=)。VFIO（Virtual Function I/O）是内核中的框架，允许在用户态安全地控制物理设备，并将它们分配给虚拟机[[3\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=VFIO（Virtual Function I%2FO）是一个现代化的、安全的内核框架，用于在用户空间实现设备直通，例如在 QEMU%2FKVM 虚拟化环境中。`vfio,PCI 设备驱动。)[[4\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=设备直通允许虚拟机 独占 并直接访问宿主机上的一个物理硬件设备。对于虚拟机来说，这个设备就像直接插在它自己的主板上一样，从而可以获得近乎原生的性能。)。启用 VFIO 需要加载相关内核模块（如 vfio_pci, vfio, vfio_iommu_type1, vfio_virqfd 等）[[5\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=1. 启用内核模块： 确保 )。在 VM 启动时，用户态工具（如 QEMU）通过 -device vfio-pci,host=<bus:slot.func> 参数将设备传递给客机[[6\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=2)，此时设备直接映射到客机，性能接近原生[[4\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=设备直通允许虚拟机 独占 并直接访问宿主机上的一个物理硬件设备。对于虚拟机来说，这个设备就像直接插在它自己的主板上一样，从而可以获得近乎原生的性能。)。

## KVM 环境下的硬件直通

KVM 本身是 Linux 内核中的虚拟化模块，提供 CPU 虚拟化支持。**KVM** **并非 IOMMU/VFIO** **的唯一接口**，但在 KVM+QEMU 环境中，它是最常用的方案。要在 KVM 中使用 PCI 直通，需要在 BIOS 中启用 VT-d/AMD-Vi，并在内核启动参数中加入相应选项。例如，在 Intel 平台添加 intel_iommu=on[[1\]](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/5/html/virtualization/chap-virtualization-pci_passthrough#:~:text=2. Activate Intel VT,the kernel)（在 AMD 平台添加 amd_iommu=on[[2\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=)）。这些参数让 Linux 激活 IOMMU 支持，同时通常也会加入 iommu=pt（pass-through 模式）以优化性能[[2\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=)。之后，加载 VFIO 模块并让其占用欲直通的设备。通常建议在启动时通过 GRUB 参数提前绑定设备到 vfio-pci 驱动，如 vfio-pci.ids=厂商ID:设备ID[[6\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=2)[[5\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=1. 启用内核模块： 确保 )。这样一来，宿主机不会加载该设备的默认驱动，而 vfio-pci 接管设备。最后使用 QEMU 启动虚拟机时，使用 -device vfio-pci,host=<地址> 将设备直通给虚拟机[[6\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=2)。对于 KVM VM，libvirt/virt-manager 提供了便捷的配置方式（在 XML 中使用 <hostdev> 元素配置设备直通），但底层原理与上述一致。

值得注意的是，KVM 环境下还有两种“直通模式”：**托管模式（****managed****）**和**非托管模式（****unmanaged****）**。托管模式下，libvirt 会在 VM 启动时自动解绑设备，并在 VM 关闭后重新绑定给宿主；非托管模式需要管理员手动解绑再绑定[[7\]](https://blog.csdn.net/weixin_42834523/article/details/120544068#:~:text=PCI设备可以在两种模式下连接，“托管”或“非托管”模式，尽管在编写本文时只有KVM支持“托管”模式连接。在托管模式下，当客户端启动时，所配置的设备将自动与主机 的操作系统驱动程序分离，当客户端关闭时，将重新连接所配置的设备。在非托管模式下，必须在启动客户机之前显式分离设备。如果设备仍然连接到主机操作系统，客户端将拒绝启 动。libvirt ‘Node Device’,api提供了一种从主机驱动程序分离%2F重新连接PCI设备的方法。或者，主机操作系统可以配置为将来宾操作系统使用的P CI设备列入黑名单，这样它们就永远不会连接到主机操作系统驱动程序。 在这两种模式中，虚拟化技术总是在启动客户机之前和关闭客户机之后在设备上执行重置。这对于确保主机和客户操作系统之间的隔离至关重要。PCI设备有多种复位方式。一些复 位技术局限于单个设备%2F功能，而另一些可能同时影响多个设备。在后一种情况下，将有必要将所有影响设备分配给同一来宾，否则将不可能安全地进行重置。通过手动解绑定设备，)。不过这些机制属于管理层面，不改变硬件直通的核心要求。



## 其他虚拟化技术的硬件直通

- **Xen** **虚拟化**：Xen 是一种 Type-1（裸金属）虚拟机监控器，也支持 PCI 直通。Xen 同样依赖 IOMMU，需在 Xen 的启动参数中添加 iommu=on[[8\]](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/5/html/virtualization/chap-virtualization-pci_passthrough#:~:text=Xen and KVM require different,follows to enable PCI passthrough)。Red Hat 文档指出“Xen hypervisor     支持将主机上的 PCI 设备直通给虚拟机”[[9\]](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/5/html/virtualization/chap-virtualization-pci_passthrough#:~:text=This chapter covers using PCI,with Xen and KVM hypervisors)。在 Dom0 中，管理员可使用 Xen 的 pci-backend （如 xen-pciback 或新版 XCP-ng 的 IOMMU PV 支持[[10\]](https://xcp-ng.org/blog/2024/04/18/iommu-paravirtualization-for-xen/#:~:text=Xen and IOMMU)）将物理设备隐藏并分配给 DomU。Xen 也利用 IOMMU 对设备 DMA 进行隔离[[11\]](https://xcp-ng.org/blog/2024/04/18/iommu-paravirtualization-for-xen/#:~:text=Xen already leverages the IOMMU,interface to the guest to)，确保安全；对于 Xen VM，通过其配置工具（xl、XenCenter 或 libvirt 的 Xen 驱动）来指定要直通的设备即可。
- **纯 QEMU****（无 KVM****）**：即完全的软件模拟模式。理论上，QEMU 即使不加载 KVM 模块，也可以启用 VFIO 将设备直通给 guest，但 CPU 全部由软件模拟，性能远逊于使用 KVM。也就是说，**硬件直通本身不依赖** **KVM**，而是依赖 IOMMU 与 VFIO 框架；如果不启用 KVM，QEMU 仍可执行 -device vfio-pci,host=... 来传递设备[[6\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=2)，仅 CPU 仿真会明显变慢。因此，纯 QEMU 可以实现设备直通，但通常只在测试或无须高性能时使用。
- **LXC/LXD** **容器**：LXC 并非硬件虚拟化技术，它共享宿主机内核，不使用专门的 IOMMU 通道。标准容器无法像虚拟机那样通过 IOMMU 独占 PCI 设备。通常的做法是**通过挂载设备节点和设备权限控制**，让容器访问主机设备。例如，可以在容器配置中设置 lxc.cgroup2.devices.allow 允许访问特定设备号，并使用 lxc.mount.entry 将 /dev/dri/card0、/dev/dri/renderD128 等主机 GPU 设备节点挂载到容器中[[12\]](https://blog.hellowood.dev/posts/在pve的lxc容器中直通核心显卡/#:~:text=的字符设备节点拥有读、写和映射（rwm）的权限。用于允许容器内的进程访问特定的设备，如图形加速设备。)。这样容器内的应用就能使用 GPU 加速，类似硬件直通的效果。但这依赖于宿主机驱动的存在，并不是利用 IOMMU 做隔离，只是将设备文件权限开放给容器，因此安全隔离性较低。总之，LXC 本身不需要也不使用 KVM；其“直通”更像资源共享而非真正的硬件直通。
- **Virt-Manager/Libvirt**：Virt-Manager 是一个图形管理工具，通过     libvirt 管理虚拟机。它本身不提供虚拟化功能，只是对 KVM/QEMU、Xen、LXC 等进行统一管理[[13\]](https://blog.csdn.net/weixin_42834523/article/details/120544068#:~:text=PCI设备直通功能允许将主机上的物理PCI设备直接分配给来宾机。客户操作系统驱动程序可以直接使用设备硬件，而无需依赖主机操作系统的任何驱动程序功能。 在使用PCI设备直通时需要注意一些事项。当将PCI设备直接分配给客户机时，如果不首先从客户机热拔下设备，迁移是不可能的。此外，libvirt并不保证直接设备分配 是安全的，将安全策略决策留给底层虚拟化技术。安全PCI设备透传通常需要特殊的硬件功能，例如用于英特尔芯片组的VT)。因此，通过 Virt-Manager     配置直通时，实际调用的仍是底层的 KVM/VFIO 或 Xen 机制。例如，在 libvirt XML 中定义 <hostdev> 元素时，如果后台选择 KVM，Virt-Manager 会在启动 QEMU 时加 -device vfio-pci；如果后台选择 Xen，则使用 Xen 的方法。Virt-Manager 也支持直接管理 LXC 容器，但容器直通同上所述，通过文件挂载和 cgroup 实现。



## 关键组件与配置

- **内核模块**：kvm, kvm_intel（或 kvm_amd）提供 CPU 虚拟化支持；vfio, vfio_pci, vfio_iommu_type1, vfio_virqfd 等提供 IOMMU 隔离和设备直通支持[[5\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=1. 启用内核模块： 确保 )；Xen 环境则需 xen hypervisor 相关模块（如 xen-pciback）；容器无额外虚拟化模块，但访问物理设备时依赖宿主驱动。
- **内核启动参数**：启用 IOMMU 是前提。在 Intel 系统常加 intel_iommu=on，在 AMD 系统加 amd_iommu=on[[2\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=)；通常同时加 iommu=pt（pass-through）提升性能[[2\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=)。在 Xen 上，还需给 Xen hypervisor kernel 添加 iommu=on[[8\]](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/5/html/virtualization/chap-virtualization-pci_passthrough#:~:text=Xen and KVM require different,follows to enable PCI passthrough)。根据不同平台，可能还需要 pci=realloc、pci=acs_override=downstream 等参数来优化设备复位和 ACS 分组情况。
- **用户空间工具**：KVM 常用 qemu-system-x86_64（QEMU/KVM）启动 VM，在命令行中使用 -device vfio-pci,host=<地址> 指定直通设备[[6\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=2)。使用 libvirt 时，可用 virsh nodedev-detach 或 XML hostdev 配置设备。Xen 下使用 xl 或 GUI 工具指定 pci=assign,...。LXC 则通过 lxc-attach 进入容器后使用设备节点，或通过 lxc config 配置文件调整设备权限。Virt-Manager、virsh 则是跨技术的管理接口，用来编辑并应用上面提到的配置。
- **配置示例**：以下为 KVM+QEMU 环境的典型步骤：BIOS 启用 VT-d；编辑 /etc/default/grub，添加 intel_iommu=on iommu=pt vfio-pci.ids=<厂商:设备ID>[[2\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=)[[5\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=1. 启用内核模块： 确保 )；重建 initramfs 并重启；加载模块 modprobe vfio_pci；使用 lspci -k 验证设备由 vfio-pci 驱动占用；然后通过 qemu ... -device vfio-pci,host=01:00.0     启动虚拟机[[6\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=2)。对于 Xen，只需在 Xen 的启动项里加 iommu=on，然后在 Dom0 或 VM 配置中指定要直通的 PCI 地址即可[[8\]](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/5/html/virtualization/chap-virtualization-pci_passthrough#:~:text=Xen and KVM require different,follows to enable PCI passthrough)[[11\]](https://xcp-ng.org/blog/2024/04/18/iommu-paravirtualization-for-xen/#:~:text=Xen already leverages the IOMMU,interface to the guest to)。LXC 则在容器配置 /etc/pve/lxc/<id>.conf 中添加类似示例所示的 lxc.cgroup2.devices.allow 和 lxc.mount.entry 条目[[12\]](https://blog.hellowood.dev/posts/在pve的lxc容器中直通核心显卡/#:~:text=的字符设备节点拥有读、写和映射（rwm）的权限。用于允许容器内的进程访问特定的设备，如图形加速设备。)，以允许容器访问特定设备节点。

总之，实现硬件直通的核心是**启用** **IOMMU** **并使用 VFIO** **框架**，[[3\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=VFIO（Virtual Function I%2FO）是一个现代化的、安全的内核框架，用于在用户空间实现设备直通，例如在 QEMU%2FKVM 虚拟化环境中。`vfio,PCI 设备驱动。)[[4\]](https://blog.csdn.net/shenjunpeng/article/details/154060519#:~:text=设备直通允许虚拟机 独占 并直接访问宿主机上的一个物理硬件设备。对于虚拟机来说，这个设备就像直接插在它自己的主板上一样，从而可以获得近乎原生的性能。)与 KVM 模块本身并无严格从属关系。KVM 只是众多支持 PCI 直通的虚拟化方案之一[[9\]](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/5/html/virtualization/chap-virtualization-pci_passthrough#:~:text=This chapter covers using PCI,with Xen and KVM hypervisors)，同样可由 Xen、纯 QEMU 或在一定程度上由容器共享模式实现类似功能。关键在于：硬件和内核层面需要支持（IOMMU、vfio_pci），然后交由相应的虚拟化管理工具（QEMU/KVM、Xen 或容器配置）去使用这些功能。因此，**KVM** **并非硬件直通的必要条件**，但在 Linux 上常配合 QEMU 一起使用以获得完整的 CPU 和设备虚拟化支持。
